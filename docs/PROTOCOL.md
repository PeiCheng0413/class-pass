# class-pass 協定 CP1

一個學生、一個遊戲，產生**一張** QR code，裡面裝他目前過關的所有關卡。老師掃一次就能收齊。
學生只用班級＋座號識別，不存姓名。
QR code 的內容是下面這一行文字（UTF-8）。老師端 app 只認這個格式，新遊戲照著產生就能收，app 不用改。

```
CP1|遊戲代號|班級|座號|關卡清單|簽章
```

一共 6 個欄位，用 `|` 分隔。

關卡清單裡有一到多個關卡，關卡之間用 `;` 分隔；每關有 5 個子欄位，用 `~` 分隔：

```
關卡代號~關卡名稱~分數~滿分~完成時間
```

例：

```
CP1|robot-farm-practice|701|7|check-dry~澆水~3~3~1760000000;harvest~收成~2~3~1760000300|簽章
```

## 欄位

主欄位：

| # | 欄位 | 規則 | 例 |
|---|------|------|----|
| 1 | 版本 | 固定是 `CP1` | `CP1` |
| 2 | 遊戲代號 | `[A-Za-z0-9-]{1,40}` | `robot-farm-practice` |
| 3 | 班級 | 學生輸入的文字，1–20 字 | `701` |
| 4 | 座號 | 1–999 的十進位整數 | `7` |
| 5 | 關卡清單 | 1–30 關，見下表 | |
| 6 | 簽章 | 見下方「簽章」，固定 16 個字元 `[A-Za-z0-9_-]` | `SjdxLZjvH956zyUB` |

每一關：

| # | 子欄位 | 規則 | 例 |
|---|--------|------|----|
| 1 | 關卡代號 | `[A-Za-z0-9-]{1,40}`；同一張 QR 裡不可重複 | `check-dry` |
| 2 | 關卡名稱 | 給人看的文字，1–10 字；遊戲沒給名稱時就填關卡代號 | `澆水` |
| 3 | 分數 | 十進位整數，`0 ≤ 分數 ≤ 滿分` | `3` |
| 4 | 滿分 | 十進位正整數 | `3` |
| 5 | 完成時間 | Unix 秒，十進位整數 | `1760000000` |

整數一律不帶正負號，也不補前導零。學生輸入座號 `07` 時，網頁端要轉成 `7`，免得同一個人被當成兩個人。
關卡的先後順序沒有意義，網頁端按照完成時間排。
「字」指的是 Unicode 字元（code point），中文一個字就算一字。

### 文字欄位的清理

適用欄位：班級、關卡名稱。

網頁端在**存檔與簽章之前**做以下處理。app 端不做任何轉換，直接拿收到的位元組去驗簽：

1. Unicode 正規化成 NFC。
2. 移除 `|`、`;`、`~`、換行（`\r`、`\n`），以及其他控制字元（U+0000–U+001F、U+007F）。
3. 去掉頭尾的空白。
4. 截斷到字數上限。
5. 清理後不可以是空字串（關卡名稱清理後如果是空的，就改用關卡代號）。

中間的空白會保留。

## 簽章

```
簽章 = base64url( HMAC-SHA256( 金鑰, 前面整段文字 ) ) 的前 16 個字元
```

- 「前面整段文字」：從 `CP1` 開始，一直到關卡清單後面那個 `|`（**包含**這個 `|`），用 UTF-8 編成位元組。
- base64url 使用 `A–Z a–z 0–9 - _` 這些字元，不補 `=`。取前 16 個字元，等於 HMAC 的前 96 位元。
- 驗簽時要用固定時間比較（Kotlin 用 `MessageDigest.isEqual`）。

### CP1 金鑰

```
7wtYq6EDHQJxEa6gbWgOLRac-2bzsmJv
```

金鑰就是這 32 個 ASCII 字元本身的位元組，不要再做 base64 解碼。

這把金鑰會跟著網頁送到學生端，懂技術的人挖得出來；判斷國中生目前破解不了，接受這個風險（已定案，見 `REQUIREMENTS.md`）。
日後要換金鑰或改格式，就升版成 `CP2`，app 要能同時認得新舊版。

## app 端驗證規則

收到掃描內容後依序檢查，只要有一條不符合，就判定為「無效」（畫面變紅色，並播放錯誤音）：

1. 用 `|` 切開剛好是 6 段，而且第 1 段是 `CP1`。
2. 簽章正確。
3. 各欄位、各關卡都符合上面兩張表的規則，而且關卡代號沒有重複。

完成時間只記錄，不拿來擋（學生電腦的時鐘可能不準）。

一張 QR 會拆成「一關一筆」來存。同一個學生（遊戲＋班級＋座號）的同一關，只留最好的成績：分數比較高的勝出；分數相同時，留完成時間比較早的那一筆。

## 測試向量

網頁端（Web Crypto）和 Python（`hmac`）算出的結果相同，Kotlin 的單元測試也要用這幾筆。

有效：

```
CP1|robot-farm-practice|701|7|check-dry~澆水~3~3~1760000000;harvest~收成~2~3~1760000300;sort-seeds~分種子~3~3~1760000900;night-watch~守夜~1~3~1760001500|SjdxLZjvH956zyUB
CP1|demo|8年3班|23|level-2~level-2~85~100~1760003600|627Pc4prOkVRT51j
```

無效（以第二筆為基礎，每筆只改一處）：

```
CP1|demo|8年3班|23|level-2~level-2~85~100~1760003600|627Pc4prOkVRT51X   簽章錯一個字
CP1|demo|8年3班|23|level-2~level-2~95~100~1760003600|627Pc4prOkVRT51j   分數被改
CP1|demo|8年3班|23|level-2~level-2~85~100~1760003600                    少了簽章
CP2|demo|8年3班|23|level-2~level-2~85~100~1760003600|627Pc4prOkVRT51j   不認得的版本
```

另外，簽章正確但內容違反規則的情況，Kotlin 測試要自己用金鑰簽出來再驗，例如：關卡代號重複、分數大於滿分、座號 `07`、關卡名稱超過 10 字。
